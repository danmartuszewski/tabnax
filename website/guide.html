01 / BUILD LOCALLY

Start with the native app.

You’ll need an Apple silicon Mac running macOS 15 or later, Xcode with the macOS 26 SDK or newer, and its command-line tools selected. Obtain the project source from its owner; a public repository address has not been configured yet.

From the project’s root directory:

make build
open macos/build/DerivedData/Build/Products/Debug/Tabnax.app --args --settings

Or run make dev to rebuild and reopen as native source changes. You can also open macos/Tabnax.xcodeproj and run the Tabnax scheme. The shared project uses ad-hoc signing without a private certificate.

  1. Open Settings → General and allow Accessibility for the exact app build.
  2. Return to Tabnax and select Retry.
  3. Press ⌃ ⌥ Space, then type a destination’s displayed address.

App settings include the activation shortcut, persistent app letters, mouse controls, display placement, six themes, and browser connections. Letter changes use Apply/Discard; other preferences save immediately.

02 / CONNECT BROWSERS

Your tabs belong here, too.

BrowserConnection and setup
Arc, Chrome, Edge, BraveBuilt-in Apple Events. Use Set up in Browser tabs and approve macOS Automation for each browser.
Firefox, ZenCompanion extension and native messaging. Set up registers the local host and opens the installation guide. Current development installation is temporary; permanent installation requires a signed add-on.
SafariEmbedded Safari web extension. Approve it in Safari’s extension settings. Development builds may require Safari’s unsigned-extension setting.

Private tabs are excluded. Choose all available browsers or a subset, and limit tabs to all, the active browser, or its active window. A checked preference does not bypass browser consent.

03 / PERMISSIONS & PRIVACY

Local by design.

The current app processes window and tab metadata locally, stores settings on your Mac, and has no cloud account or analytics service. Accessibility enables window discovery, focus, and keyboard capture. Browser Automation and extension approval are separate. Launch at login is optional.

Tabnax does not request Screen Recording or an additional Input Monitoring permission. Companions use tab metadata and native messaging without page-content scripts or browsing-history access.

The website demo uses sample data. It cannot discover real windows, launch apps, or change native preferences. Native images are app-owned view exports; glass appears opaque in those exports.

Compatibility across Spaces, full-screen apps, Stage Manager, input utilities, and display arrangements still needs broader testing. Development builds are not signed/notarized public releases.
