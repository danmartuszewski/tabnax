# Functionality and defaults matrix

This is a prioritized design inventory. The user requested placement, browser tabs, customizable presets and coverage of all six display modes; the prototype includes them. See [the six-mode matrix](./SIX-MODE-COVERAGE.md). Native implementation and browser coverage still require verification. **Essential** = recommended core; **Advanced** = useful only after the baseline; **Conditional** = depends on a chosen mode/capability; **Deferred** = intentionally absent. A capability does not automatically create a setting. Defaults are recommendations unless the brief explicitly fixes them. See [specification](./SPECIFICATION.md) for input and permission contracts.

## User-facing preferences

| Setting / class | User problem | Recommended default | Allowed values | Dependencies & validation | Behavioral effect / application |
| --- | --- | --- | --- | --- | --- |
| Open switcher · Essential | Reach the app without mouse travel | Suggest Control-Option-Space during setup; verify before activating | One recorded key plus supported modifiers | Reject bare typing keys and known reserved shortcuts; registration can fail; test with Mouseless; retain old shortcut on failure | Opens a session only on validated activation; committed transactionally |
| Behavior · Essential choice, hold advanced | Some users cannot or prefer not to maintain a chord | Press to open | Press to open; Hold to show after native feasibility | Hold requires reliable down/up capture and supported input transport | Latched mode survives release; hold is owned by the modifiers rather than the trigger key — releasing them after cycling commits the highlight, releasing them without cycling cancels without selection |
| Modifier side · Advanced | Use one hand to activate without intercepting the other hand | Either side | Either; Left only; Right only for eligible chord components | Disabled with an explanation if transport lacks side identity; validate remappers, Sticky Keys and both-sides-held | Filters trigger identity; independent of selection alphabet; cancels open session on change |
| Mouse control · Requested / planned | Choose with mouse after shortcut activation | Click to select, preserving current clicks and content scrolling | Off; Click to select; Click + wheel selection | Active-session and exact-surface gating; mode-aware branches; trackpad normalization; preserve keyboard/accessibility activation | One General setting shared by all six modes; wheel never commits; [detailed plan](./plans/MOUSE-CONTROL-PLAN.md); not implemented yet |
| Modifier-only tap · Deferred | Reuse a comfortable single modifier | Unassigned | At most one explicit spare modifier, tap or hold, if later supported | Must not take Mouseless default trigger; uninterrupted tap recognizer; ordinary shortcuts pass through | No baseline dual tap/hold behavior or timing controls |
| Selection hand · Essential | Comfortable selection opposite activation hand | Right hand | Right; Left; Both; Custom | Preset replaces a draft alphabet only; does not automatically move activation | Right `JKLUIONMHP`; left `ASDFWERCGQ`; both `ASDFJKLWERUIOP`; Apply labels required |
| Ordered alphabet · Essential | Match actual reach and learned habits | `JKLUIONMHP` | Study: 6–20 unique ASCII letters; native: approved key-token alphabet | Whitespace/case normalized; duplicates, punctuation, command keys, dead/composition keys rejected; validate translation | Earlier keys allocated first; final key reserved for growth in stable/mnemonic policies; preview actual changed labels |
| Restore default order · Requested recovery | Recover the preset after custom letter edits | Reference Right/Left/Both hand preset | Restore complete reference alphabet; disabled when already default | Preserve hand origin; validate all affected maps and pins | Draft only, then Apply/Discard; Undo; keeps policy and unrelated settings |
| Use suggested shortcut · Recovery | Recover the suggested chord after recording another | Control-Option-Space suggestion | Restore chord only | Native registration must succeed before replacing working shortcut | Keeps activation behavior and modifier side; Undo |
| Restore one theme color · Recovery | Undo one color experiment without losing others | Curated token for current preset and appearance | Key background or selection accent | Remove only corresponding override and recalculate contrast | Immediate, persisted, Undo; keeps other color/appearance/presets |
| Remove I/O · Advanced editing action | Visually ambiguous letters | No exclusion: distinct uppercase key font, no digits in alphabet | Remove I/O from current draft; can type them back | Still must satisfy minimum length; can invalidate pins; never silently modifies saved labels | One editor action, not another permanent boolean; explicit apply |
| Assignment policy · Stable essential; alternatives advanced | Balance ease of initial recognition against repeatability | Stable | Stable; Name initials first; Always two letters | Prefix-free valid pool; existing labels stable between explicit applications; pairs capacity differs | Reassignment preview; stable remains prominent recommendation; alternative chooser may stay behind Advanced in shipping MVP; Fold uses stable app/child stages, tabs use pairs |
| Key interpretation · Advanced | Keep finger locations or follow active text layout | Physical positions using explicitly shown base layout | Physical positions; Typed characters | Native layout capture/translation verified; cancel composition or unsupported mappings, never guess | Positions preserve motor habit; characters follow emitted characters; explicit text search always normal text |
| Session window pin · Advanced / optional study | Reserve a personally meaningful label for one known window | None | Existing complete unused label in this namespace | Exact live identity; reject duplicate, occupied, retired, prefix, invalid alphabet or overlength code | Only that target changes; old code retires; session-only; Apply labels + Undo |
| Persistent app pin · Deferred | Keep an app address after relaunch | None | Future app bundle/process-independent namespace reservation | Only app scope/Fold app stage; app identity collision policy required | Must not ambiguously mean “any Safari window”; no persistent window-title matching |
| Reset label assignments · Advanced action | Recover compact labels after much churn | Never automatic | Preview reset, then Apply | Shows changes, clears session pins and retired labels; Undo available | Fresh map for current catalogue; no hidden timer or compaction |
| Display mode · Requested | Choose the switching presentation | Shore | Shore; Beacons; Canopy; Lattice; Fold; Relay | Implemented mode renderer; Apply/Discard label drafts first | Cancels partial input; preserves flat/Fold addresses and per-mode placement |
| Appearance · Essential | Match system or personal light sensitivity | System | System; Light; Dark | System theme observable; forced appearance affects Tabnax only | Sample immediate, persisted; live native switcher uses next-session snapshot |
| Theme preset · Requested | Match the original green or native Mac appearance | macOS (`graphite`) | macOS; Tabnax; Sage; Iris | Curated light/dark surfaces and text; verified contrast | Changes surfaces, key treatment and selection accent; preserves icon colors, labels and order |
| Theme customization · Requested | Adjust a preset to taste | No overrides | Key background and selection accent; separate per preset and light/dark | Automatically readable key text; visible selection accent; valid hex colors | Immediate preview/persistence; reset selected preset across appearances; Undo |
| Switcher position · Requested | Predictable location | Active-window display, mode-specific anchor, 24 pt inset | Active-window / pointer / main display; nine anchors; 12–64 pt inset in 4 pt steps | Clamp within usable screen; snapshot display on opening; fallback when disconnected | Separate placement for each mode; windows/tabs share that placement, except Beacons plaques; current-mode reset and Undo |
| Browser choice · Requested | Use preferred browsers with little setup | All available supported browsers | Automatic; selected subset of Arc, Zen, Safari, Chrome, Firefox, Edge and Brave | Read-only discovery; consent and add-on setup only when needed; never treat checkbox as access | Excludes targets without freeing labels; persists subset; guided setup; Undo |
| Browser tabs · Requested | Reach an individual browser tab | Enabled, all included browsers; Windows opens first | On/off; all / active browser / active window; default Windows/Tabs | Verified adapter and actual consent before native enumeration; separate pair namespace; private excluded | Five-pane toolbar; `1`/`2` scope commands; filters retain labels; Arc/Zen/Safari/Chrome/Firefox/Edge/Brave samples only |
| Label size · Essential accessibility | Read keys comfortably | Standard | Standard; Large; Extra large | Native title/UI scaling must also support enlargement; no clipping | Study 12/17/24 px badges; native start ≥13 pt and support 200%; sample immediate |
| Stronger outlines · Advanced legibility | Distinguish key bounds | Off, unless system demands more contrast | Off; On | Increase Contrast overrides a weaker choice | Stronger edge, never reduced contrast; no OS-setting duplicate |
| Include minimized windows · Essential | Reach work put away in the Dock | On | On; Off | Backend can identify and restore exact window; unavailable state otherwise | Filters eligibility next session, never frees labels; sample responds immediately |
| Include windows of hidden apps · Essential | Reach hidden work without app hunting | On | On; Off | Backend must distinguish hidden status from failed enumeration | Same filtering contract; target includes hidden marker |
| Launch at login · Essential convenience | Have switching available after login | Off | Off; On; actual status pending/approved/denied | User action; native service registration and OS approval status | Saves intention plus reflects actual availability; study changes no login item |
| Accessibility status · Essential capability, **not a toggle** | Understand why switching is unavailable | Unknown until queried | Not requested; denied; granted; revoked; unavailable | Native trusted-state query; never inferred from a clicked button | Explain, open appropriate System Settings action, recheck on return; revoke cancels input |
| Restore defaults · Essential action | Recover from confusing customization | User invoked only | All Tabnax preferences and session labels; permissions excluded | Concise confirmation with scope; backup/Undo before mutation | Atomic restore; no removal of OS consent; no window closing |

## Product decisions that must not become switches by default

| Capability / class | Problem and default | Permissible policy, dependencies and validation | Effect / UI decision |
| --- | --- | --- | --- |
| Icons and titles · Essential | Recognize same-app windows; icon + concise distinguishing title | Full original title remains accessible; no title used as persistent identity; native title differentiation must be verified | Always present; no “show icons” toggle; no screenshot previews |
| Stable labels · Essential invariant | Learned keys must remain meaningful | Confirmed live identity, generation-aware catalogue, explicit new address session | Never MRU-sort labels or reassign on title change; no toggle for silent reshuffling |
| Sequence commit · Essential invariant | Fast remembered input | Prefix-free exact match; no timing ambiguity; ignore autorepeat and unrelated modifiers | Immediate final-key intent; no Enter confirmation or sequence timeout setting |
| Cancellation · Essential invariant | Recover without switching the wrong window | Escape/backspace rules; focus loss, lock, permission loss and stale input cancel | No confirmation on cancel; no accidental “return focus” to obsolete target |
| Active session snapshot · Essential invariant | Prevent settings/catalogue changes stealing a typed label | Immutable map/input route; confirmed close disables target; new targets wait | No live reassignment beneath input; OS accessibility may strengthen current rendering |
| Window eligibility · Essential invariant | Avoid menus, desktop surfaces and duplicate sheets | Role/subrole rules; own windows excluded; recoverable failures do not imply closure | A short explanation, not one checkbox per window class |
| Screen placement · Requested | Find the overlay consistently | Explicit display and anchor, frozen during a session; clamp to visible frame; fallback to main when needed | Position pane controls panel placement. Beacons plaques still track their windows |
| Spaces / full screen · Conditional | Reach windows elsewhere reliably | Backend availability contract; no public-API claim from the simulation | No current-Space filter until membership can be determined; unavailable target is explicit |
| `/` search · Conditional enhancement | Find a forgotten label or address-exhausted target | Explicit mode; literal AND substring baseline; no external data; Enter result selection | No fuzzy-versus-literal preference; adopt only if it helps larger/ambiguous sets |
| Window/app scope · Conditional | Choose an app with no open windows | Windows default; optional running-app namespace; scope shown | Never launches installed but non-running apps; no scope picker with one supported scope |
| Shore placement · Required for Shore | Edge index reach and scan | Use the mode’s preferred anchor and edge spacing; labels stable when rows compact | No per-window coordinates |
| Beacons placement · Required for Beacons | Recognize visible geography | Plaque collision handling and out-of-sight bank; native geometry gate | Automatic placement; no per-window offsets or screenshot permission |
| Canopy grouping · Required for Canopy | Distinguish windows of same app | Group visually by app; complete direct labels remain window addresses | No forced app prefix; not a group editor |
| Lattice geometry · Required for Lattice | Learn address locations | Fixed slots with held holes; bounded viewport; overflow branch visible | Start with automatic geometry; no per-level row/column editor unless clearly needed |
| Fold namespaces · Required for Fold | Reduce competition among sibling windows | App-stage allocator plus one window allocator per app; singleton still two stages | App and child alphabets initially shared; no third tab hierarchy by default |
| Relay return · Required for Relay | Alternate two windows with low recall | Previous distinct live window; Enter clearly a command; history only on actual focus success | No frequency slider; direct letters unchanged |
| Browser adapters · Requested; implementation gated | Reach exact tabs and their parent windows | Per-browser consent, connection generation, tab identity and verified focus | Browser Tabs pane is included; Arc/Zen required; seven proposed browsers, with native adapters unverified |
| Excluded apps · Deferred advanced | Keep a specialized tool out of the index | Stable bundle identifiers; explicit list and reset; avoid title patterns | Add only with actual exclusion use cases; no default deny list beyond system surfaces |
| Motion / transparency / contrast · Essential system behavior | Accessible rendering | Always respect OS settings, use semantic colors and opaque backing | No app toggles that negate OS needs; harness toggles are test-only |
| Full theme designer / profiles / import-export · Deferred | Share configurations or alter every visual token | Additional versioning and recovery required | Four presets and constrained color customization are included; fonts, blur, geometry and sharing remain deferred |
| Weighted frequency / recency assignment · Rejected | Put popular targets under easy keys | Automatically changing keys conflicts with learning | No setting; a user can manually reserve an app later without hidden scoring |
| Performance, polling, event tap priority · Internal | Reliable native responsiveness | Measure and choose implementation policy | No “fast mode,” polling interval, transport selector or debug key logging in product settings |
| Updates · Conditional on distribution | Stay current | Native distribution/updater chosen separately | Standard update flow outside this design; no fake update toggle |

## Priority and effort, without scope commitment

| Design tranche | Effort | Acceptance to proceed |
| --- | --- | --- |
| Essential settings + stable allocator + six mode previews | M | User can change mode, hand and theme, understand each mode’s grammar, and recover a bad configuration unaided |
| Native activation/permissions/identity validation | L | Measured reliable input and exact-window focus across the supported envelope |
| Optional policy/pin/search alternatives | M | Demonstrated reduction in hesitation/errors without surprising relabeling |
| Browser adapters and native placement | L | Requested scope; validate exact-tab focus and screen behavior for the chosen browser matrix |
| Full theme designer and persistent window mappings | XL / deferred | Separate approved product use case and feasibility evidence |

These are relative sizes, not calendar forecasts or implementation authorization.
