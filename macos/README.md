# Tabnax for macOS

A native menu-bar switcher for macOS 15+ on Apple silicon, built with Swift 6, AppKit and SwiftUI. The seven settings panes build on the [settings design](../settings-exploration/README.md): General, Letters, Apps, Exclusions, Position, Appearance and Browser tabs. The live preview uses the same native renderer as the real switcher. All six display modes support windows, browser tabs, assigned app launching and explicit search. Shore, Beacons, Lattice and Relay also show running app rows; Fold and Canopy group windows and tabs under their owning apps.

## Build and run

Requires Xcode with the macOS 26 SDK or newer, Swift 6, and its macOS command-line tools. The only third-party dependency is [Sparkle](https://sparkle-project.org) 2.10.0 for updates, resolved by Swift Package Manager and pinned in `Package.resolved`; the first build needs network access to fetch it. Debug builds do not start the updater. Shared builds use ad-hoc signing and do not require a certificate named for a particular developer. For an optional local certificate override, see [development signing](../docs/DEVELOPMENT.md#native-development-signing).

```sh
./macos/scripts/build.sh
open macos/build/DerivedData/Build/Products/Debug/Tabnax.app --args --settings
```

Or open `macos/Tabnax.xcodeproj` and run the shared **Tabnax** scheme. `./macos/scripts/build.sh Release` creates the optimized build. Build products stay under `macos/build/`. No installation, login registration or permission grant occurs during a build.

### Automatic rebuild and reload

Double-click **Run Tabnax.command** in this folder, or run this from the project root:

```sh
./macos/scripts/dev.sh
```

Leave that terminal open while testing. Saving native source, package code, app resources or Xcode project changes triggers an incremental Debug build and reopens Settings. Type **r** and press **Enter** to rebuild manually. **Ctrl-C** stops the watcher and leaves the app open. `./macos/scripts/dev.sh --once` builds and reopens once.

This is a full native app restart; saved settings and window size survive. Apply pending label edits before reloading. The development app stays at `macos/build/dev/Tabnax.app`, with separate build output in `macos/build/DevDerivedData/` and diagnostics in `macos/build/dev/build.log`. A build/signature failure leaves the running app intact; a failed launch attempts to restore the previous development bundle. The runner only closes this project's Debug, Release and development app copies, and refuses to launch alongside an unrelated installed copy. It does not install the app, register login items or grant permissions.

Only one runner can be active per project. Build output, Xcode user state and editor temporary files are ignored. Changes saved during a build trigger another build afterward. Changes to the watcher scripts themselves require restarting the command. Browser design HTML is a separate preview; companion-extension changes may still require reloading that extension in its browser.

The app lives in the menu bar. Settings → General shows observed Accessibility and login-item status. Accessibility enables cross-app window discovery, exact focus and the consuming keyboard event tap. Use **Open System Settings**, grant access to the exact app build, then **Retry**; an ad-hoc rebuild may require reopening or reauthorizing the app. Tabnax does not request Screen Recording or additional Input Monitoring. Browser Automation and extension approvals are separate and explained in Browser tabs.

## Use and settings

- **Control–Option–Space** opens the switcher by default. Record **Command–Tab**, select **Use ⌘ Tab**, or record another non-navigation chord with at least one modifier. Command–Tab replaces the macOS app switcher while Tabnax's keyboard capture is active; recording that system chord requires the existing Accessibility permission. The direct button works before permission is granted. Choose either/left/right modifier sides, or restore the suggested chord. Press-to-open stays open after release for custom shortcuts. Command–Tab selects the initial highlight on Command release in either behavior, so a single press switches back to the previous window. Hold-to-show keeps the modifiers down while the activation key can be released; releasing the modifiers selects the previous window or a highlight reached by keyboard cycling. Typing or quitting an app disarms release selection; restoring a minimized window preserves it. Wheel movement never arms selection.
- Type a displayed address to select immediately on its final keydown. Escape clears the prefix, then closes; Backspace goes back. A fresh activation chord toggles a latched switcher closed; re-pressing its trigger while the opening modifiers are held cycles. Arrow keys and Tab navigate; Enter selects, except Relay’s direct view where Enter returns to the previous observed window. Search uses normal Enter selection in every mode.
- **Command-Q** requests a normal quit of the highlighted app, including the app owning a highlighted window or browser tab. The app can show its usual save prompt or cancel quitting. **Press Option** after opening to restore the highlighted minimized window. Visible windows stay unchanged. An app row or Fold app group restores its most recently used available minimized window, falling back to catalogue order. With Command-Tab, press Option while holding Command, then release Command to select that restored window. Moving the highlight or typing cancels that pending release selection. With the default Control-Option-Space shortcut in press-to-open mode, release the opening modifiers first, then press Option; in hold-to-show mode, use a shortcut without Option. A subtle minus badge marks minimized window icons in every layout and app entries that contain minimized windows, including Fold’s collapsed groups. Tooltips and accessibility labels describe the state. Option leaves search text entry alone and does not act on browser tabs or ambiguous overflow groups. Quit still disarms release selection. Selecting a minimized window by its address, click or Enter continues to restore it.
- **General → Windows → Traversal order** offers **Stable** (the default), **Most recently used**, **Alphabetical**, and **Window state**. Recency lists the current window, then observed recent windows, followed by unknown windows/tabs/app rows in stable order. Alphabetical uses app name then natural title order. State puts ordinary targets before other Spaces, minimized windows, hidden apps, and unavailable targets; ties stay stable. Include-minimized/hidden and exclusion settings still apply.
- Ordering is captured when the switcher opens. Metadata, focus previews and catalogue refreshes cannot move its rows or change direct addresses; new targets wait until reopening. App layouts keep groups together, positioned by their first ordered child. Lattice keeps shared overflow branches after app-owned cells and unaddressed rows after the grid. Beacons keeps plaques beside windows and shows the remaining targets in traversal order. Relay keeps its two lead cards; optional ordering chooses those cards, while Enter retains its previous-window behavior. Cycling and modifier release select the actual highlight. Closed assigned apps retain their direct launch letters but do not occupy invisible cycling stops. Recency remains in memory and records verified foreground windows, never highlight movement or preview activation.
- **Window actions:** use the ellipsis button or **Command–Period (⌘.)** for the highlighted target in any layout, including search. The compact native menu offers Close Window, Minimize Window, Restore Window, Hide/Unhide App, Zoom Window, Toggle Full Screen and Quit App. Unavailable actions explain why in the menu. Close, minimize, zoom and fullscreen require an individual catalogue window; app rows, collapsed Fold groups and browser tabs never redirect those actions to another window. A browser tab may hide/unhide or quit its known owning app. Restore keeps the existing most-recent minimized-child behavior for app rows and Fold groups.
- Opening either the actions or keyboard-help menu keeps the switcher open after the activation modifiers are released, in both hold and press-to-open behavior. Menu arrows, Return, Escape and typing belong to the native menu; Escape closes only the menu. Search retains its insertion point. Subsequent explicit navigation can resume normal selection. The action keeps the exact target captured when the menu opened even if catalogue updates move the highlight. Close dismisses the switcher so the app's usual save/cancel prompt can be used. Other action results appear in the switcher while it remains open. Window support is checked live through public Accessibility controls; unavailable/disabled controls are never replaced by global keystrokes, guessed geometry or another window. **General → Windows → Show window actions menu** controls the button and ⌘. shortcut, defaults to on for new and existing settings, and does not change Command-Q or Option restore. The shortcut only applies inside the switcher and leaves direct letters, plain period, search typing and unrelated modified keys alone.
- Windows, browser tabs and app targets share one switcher. **/** opens explicit search with normal text input/IME handling. Search covers app, title and available browser/window context. Selecting a running app row activates the app without promising a particular window. Fold and Canopy group windows and tabs under app prefixes.
- Search accepts initials and nonconsecutive letters in each app name, title or context field: `vsc` matches Visual Studio Code and `inptrtr` matches InputRouter. Every space-separated term must match; terms never join across fields. Case, accents, character width and formatting separators are normalized. Symbols such as `+` and `#` remain meaningful. Exact, prefix and contiguous matches rank ahead of initials and looser subsequences. Letters must appear in order; search does not correct transposed, substituted or extra letters.
- Strongest matching app groups come first in Shore, Canopy, Lattice and Fold; items within each group are ranked too. Beacons and Relay search use ranked results directly. Equal scores use the chosen session order. Empty or whitespace-only searches retain the normal unranked search layout. Keyboard navigation, pointer selection and Enter share the displayed order. Closed assigned apps stay launchable by their direct letters, but are excluded from search selection because they have no visible row.
- **General → Search → Remember search choices** is off by default, including for existing preferences. Opting in remembers up to 128 recent query/target choices on this Mac and nudges similarly strong matches without changing labels or target identity. Only salted SHA-256 fingerprints are saved, never readable query/title/context history. Fingerprints are a local ranking hint, not encryption. **Clear remembered choices**, turning the setting off, or restoring defaults deletes them and rotates the salt; Undo does not restore deleted history. Search choices in the Settings preview are not recorded.

- Mouse control can be Off, Click to select, or Click + wheel selection. Wheel navigation only changes the highlight over owned switcher content. It ignores momentum, locks trackpad gestures to their starting region and never commits. Beacons uses the bank; Fold separates its app spine and child sheet. Assistive accessibility actions remain available with Mouse Off.
- **General → Mouse & trackpad → Move cursor to selected window** optionally centers the cursor after exact window focus is confirmed. It defaults to off and works independently of mouse control. Previewing highlights, cancelling, app-only activation and browser-tab selections leave the cursor alone.
- **Letters** offers right/left/both-hand orders, All letters, or 6–26 unique letters, reordering, Remove I/O and **Restore default order**. Choose stable labels, name initials first, or pairs, and physical US positions or typed characters. Manage persistent app assignments in **Apps → App letters**. **Reset letter assignments…** remains available for automatic and session letters. Letters and Apps share a draft; navigation keeps it intact, and Apply/Discard remains visible on every pane while changes are pending. Other preferences save immediately, with bounded Undo.
- **Apps → App letters** offers persistent, optional app assignments. Turn on **Use fixed app letters**, choose **Add application…**, then choose its letter from the app’s row and **Apply letters**. Letters can use A–Z outside the window alphabet; the current overflow key and letters already assigned to another app are unavailable. Fixed letters take priority over automatic app labels and also provide Fold and Canopy’s app prefixes. Automatic assignments skip those reserved keys even with **All letters** selected or while the assigned app is closed. Applying changes replaces conflicting automatic app letters, and resetting session letters preserves fixed app reservations. Flat modes allocate one shared set of addresses across apps, windows and tabs. Fold and Canopy share a separate set of app prefixes and child letters.
- **Launch assigned apps when they aren’t running** is a separate opt-in. Closed assigned apps appear in every mode with a **Launch** subtitle; their letter or click opens them through macOS Launch Services. Enter selects the highlighted target except in Relay’s direct view, where Enter retains its previous-window action. An already-running instance is activated instead. With launching off, only running apps appear, while fixed keys remain reserved. Turning off fixed letters preserves the saved assignments for later. Missing apps remain unavailable and cannot accidentally open a different application at their old path. The preview never launches anything.
- Position uses one display choice across modes and remembers the nine-position anchor and inset separately for every mode. Resetting a mode’s position preserves the shared display choice. Its illustrated desktop updates immediately using the real panel's placement calculation; the diagram's Main/External displays are examples, not a screen capture. Placement freezes when opening and stays within usable bounds. Beacons’ plaques follow their windows; its bank uses the chosen position.
- **Position → Show simultaneously on every display** is opt-in. All copies share targets, direct letters, traversal order, query/prefix, highlight, actions, theme and per-mode placement. The existing Show on choice sets initial keyboard focus; clicking another copy transfers the native editor, finishing any composition and preserving committed text and selection. Smaller screens clamp and wrap the same layout within their usable bounds. Beacons repeats its complete target bank and shows each spatial plaque only once, clear of all banks. One desktop spotlight controller serves the session. Display connection/removal, resolution changes and wake dismiss every copy; reopen to use the current screens. Settings previews remain single.
- Appearance provides Graphite, Tabnax, Sage, Iris, Frosted Glass and macOS Glass themes. The theme cards update the native preview immediately, save automatically and retain separate light/dark key and selection colors per theme. System/Light/Dark controls both Settings and the switcher. Frosted Glass uses native desktop blur; macOS Glass uses native Liquid Glass on macOS 26+, with frosted glass on earlier macOS. Reduce Transparency or Increase Contrast uses solid surfaces, while keys and selection remain readable. Scoped color resets, larger labels and stronger outlines are available. No custom animation is added.
- **Appearance → Desktop spotlight** brings the highlighted desktop window above overlapping windows, then outlines it and dims the surrounding desktop. The switcher stays open as you cycle. Preview activation does not change Tabnax's recent-window history; Escape returns to the original window, while Enter or the activation-modifier release selects the highlighted window. It starts enabled at **75% dimming opacity**, with animation enabled and the saved fast transition speed. Existing preferences are preserved. **Animate window transitions** adds a soft dim-and-reveal effect, enabled by default. The **Slow–Fast** slider controls its speed; **Try animation** plays it on the fictional example. macOS Reduce Motion disables the animation. The desktop stays dimmed between highlights, and interrupted transitions stop immediately. Turn Desktop spotlight off to disable both preview activation and dimming, or adjust dimming from **0%** (outline only) to **100%**; turning it off preserves the saved opacity. The example uses fictional windows and updates as you adjust the slider. The overlay stays below the switcher and Beacons plaques, passes mouse input through, spans displays, and disappears on selection or dismissal. It uses existing Accessibility access without screen capture. Minimized, hidden, off-Space, and unavailable windows are not previewed; selecting them uses the normal restore/focus behavior. Browser tabs and app groups have no single desktop window to preview.
- **Desktop spotlight → Focus → Switcher only** dims every display uniformly while leaving the switcher visible. Browsing does not raise or activate windows; only confirming a selection brings its target forward. This mode has its own saved dimming opacity, initially **75%**, independent of Selected window mode.

- General contains the activation shortcut, mouse control, window inclusion and a separate Startup section with **Launch at login** through `SMAppService`. The checkbox and approval status come from macOS, including changes made in System Settings. Enabling retries a missing app registration through Launch Services, and both enable and disable verify the resulting system state before saving. Registration errors preserve the working preference and appear beside the control; Open Login Items and Refresh status remain available. Browser tabs contains only browser inclusion, ranges and connections.

Settings preserves malformed or newer-version saved data instead of overwriting it. Older mode/alphabet/shortcut preferences migrate without silently changing a custom order; existing settings load with app letters and launching off. Restores and Undo do not grant/revoke OS permissions, recreate windows or restore closed tabs. Window/tab session pins last only for the target’s current lifetime; app assignments persist by bundle identity across relaunches.

## Dedicated search shortcut

General → **Open in search** offers a separate **Enable search shortcut** control. It is off for new and migrated settings; the suggested chord is **Control–Shift–Space**. The main activation shortcut remains independent. Record either chord, choose its modifier side, or reset only the search chord. Disabling retains the saved chord; Restore defaults turns the feature off. Invalid recordings and overlapping shortcuts leave saved settings unchanged and show the reason. Either-side conflicts with left/right for the same key and modifiers; distinct left-only and right-only chords can coexist. Recording suspends both activation paths.

The search shortcut opens the current layout with the native text field focused. It always stays open after modifier release, regardless of **Hold to show** or **Swap instantly on tap**, and never silently selects the previous target. From an open direct-address view it enters search in the same session, preserving frozen ordering and addresses. When already searching it refocuses the editor without clearing the query, changing the highlight or resetting composition; trigger autorepeat does nothing. Type normal text, use arrows/Tab to choose a result, and press Enter to select. Escape first exits search, then closes the switcher. This behavior applies to all six layouts, including Relay.

Both chords respect foreground shortcut exceptions and Secure Input fallback eligibility. Eligible either-side chords get separate Carbon registrations; Command–Tab and side-specific chords require the event tap. Other apps can reserve shortcuts, so choose a different chord if macOS cannot register its fallback. The fallback keeps search latched open and its native editor handles text/IME input. Keys arriving at the tap before the first search frame are queued for that editor rather than leaking to the previous app or becoming direct addresses.

Shift-only printable chords (including Shift–Space) are rejected for both shortcuts; Shift with a function key is allowed. On loading an older document that saved an unsafe Shift-only main chord, Tabnax replaces only its key/modifier combination with **Control–Option–Space**, preserving hold/latch, modifier side and unrelated preferences. Settings remain editable. If that recovery overlaps an enabled search shortcut, search is disabled until a distinct chord is chosen.

## Browsers

| Browser | Connection |
| --- | --- |
| Arc, Chrome, Edge, Brave | Built-in Apple-event adapters; Set up requests browser-specific Automation approval |
| Zen, Firefox | Shared companion extension and native messaging host; Set up registers this app’s host and opens its local installation guide |
| Safari | Embedded Safari web extension; Set up opens Safari’s extension preferences |

Automatic discovery checks installed/running browsers and existing approvals without granting anything. Use all available browsers or select a subset; filter tabs to all, the active browser, or its active window. Disabling browser tabs removes them from the shared view; windows and app targets remain available. Connection status is observed from the running adapter/companion, never inferred from a checked preference.

Private tabs are excluded. The companion asks for `tabs` and `nativeMessaging`, with no content scripts, page contents, history, profile-database access or remote debugging. The bridge uses bounded, length-prefixed JSON over a same-user Unix socket. Writes run off the UI thread with bounded backpressure. Exact tab IDs and browser/connection lifetimes are checked before selection; focus must be confirmed afterward.

**Development setup:** Firefox/Zen’s companion is currently source, with temporary installation described in [SETUP.html](BrowserCompanion/SETUP.html). Permanent Firefox/Zen installation requires a signed add-on. Safari development builds require Safari’s extension approval and may require its unsigned-extension development setting. Production signing and browser-store publication have not been performed. Selecting a browser cannot bypass browser-owned consent or these distribution requirements.

## Identity and bounded work

Stable labels prefer the app’s first letter, then other name initials and letters, then the configured letter order. Windows and tabs get first choice before app rows in flat layouts; fixed app assignments take priority over both. Allocated letters stay unchanged when names or catalogue order change. This applies to all six layouts, including existing Stable settings. The explicit pair policy still uses two-letter combinations in flat layouts.

Window identities use exact AX handles within process launch lifetimes, not guessed title/geometry matches. Labels are assigned before visibility filters. Current sessions freeze label meanings; metadata and availability can update, but new meanings enter only a fresh session. Closed labels remain reserved until reset. The shared flat pool and the grouped app-prefix/child allocation are independent.

Display connection and disconnection dismiss the switcher and refresh discovery and geometry without resetting identities or letter assignments. Work started against the previous display arrangement is discarded. If the same target temporarily disappears from the catalogue, its held shortcut is restored when it returns instead of consuming another code.

Stable labels use a spare A–Z letter outside the configured alphabet for overflow when one is available, with a four-character bound. With all 26 letters selected, the last letter is the overflow prefix. Pair policy offers `alphabet count²` addresses before the book's overall capacity limit. Fixed app letters must not collide with an overflow prefix or pair prefix. Fold and Canopy combine an app prefix and child code, collapsing single-child families to the app prefix. Exhaustion retains unaddressed targets for search/click/navigation. Resetting letters in either grouped mode resets their shared grouped allocation; other modes reset the flat pool. Fixed app assignments survive either reset.

Three bounded AX discovery workers and a serial observer-registration worker coalesce refreshes. Public geometry is read on discovery workers; uncertain Beacons visibility uses the bank. A separate focus queue checks exact focused AX identity after activation and permits one guarded repair. New input or conflicting activation cancels pending follow-up work; already-sent OS actions cannot be retracted. No periodic desktop polling, private WindowServer APIs or window-image capture is used.

AX support, modal windows, Spaces/full-screen, Stage Manager, physical input utilities and hardware display arrangements still require broader compatibility checks. Measured and unverified conditions are separated in [VERIFICATION.md](VERIFICATION.md).

## Exclusions and shortcut exceptions

**Settings → Exclusions** has independent lists for excluded apps, title rules, and foreground shortcut exceptions. Choose an installed `.app` to read its bundle identity, or enter a bundle ID directly for a closed or uninstalled app. IDs match exactly and case-sensitively; app display names and paths are not matching keys. Saved rules remain when apps quit, move or are uninstalled. Apps without bundle IDs can use all-app title rules, but cannot use app exclusions or shortcut exceptions.

App exclusions remove all of that app’s native windows, browser tabs, app rows and direct launch targets. Title rules remove individual native-window and browser-tab targets only. They never remove app rows or other windows because an app has one matching title. A browser tab is matched against its own title; native browser-window titles do not propagate to tabs because the catalogue does not have an exact cross-protocol window identity. You can scope a title rule to one bundle ID or leave the ID empty for all apps.

| Title matching | Semantics |
| --- | --- |
| Contains | Literal text anywhere in the title. |
| Equals | Literal text matching the complete title. |
| Wildcard | Complete-title match. `*` matches zero or more characters, `?` one character. `\*`, `\?` and `\\` match a literal star, question mark and backslash. Other punctuation is literal; no regular expressions or bracket classes. |

All three title modes compare Unicode lowercase text, keeping spaces, accents and punctuation significant. Wildcards count Swift `Character` values (grapheme clusters) after lowercasing. Patterns are not trimmed. Empty/whitespace-only patterns, control characters, patterns longer than 256 characters, invalid bundle IDs and unsupported/trailing wildcard escapes cannot be saved. `*` intentionally matches every title in its scope. A malformed saved rule is ignored independently; valid siblings and unrelated settings survive. Existing schema-v1 settings without these fields start with empty lists.

**Foreground shortcut exceptions** let VMs, remote desktops and games receive the original activation shortcuts without hiding their targets. The consuming event tap passes the complete key sequence. Carbon fallback registration is released while an exception app is foreground and restored after leaving it, once the trigger key is physically up. Command–Tab remains tap-only. Shortcut recording still captures the chosen chord; the menu can open the switcher explicitly. Foreground tracking samples `NSWorkspace.frontmostApplication`, keeps the last external identity across Tabnax’s own panels, and ignores spotlight preview activations. It does not use recent-window history or the highlighted target as the foreground identity.

Changes save immediately, dismiss an existing live switcher, refresh the settings preview, and support Undo. Restore defaults clears all three lists. Every layout, search, navigation and spotlight uses the filtered catalogue; queued native focus checks reject excluded identities. Rules are applied **after** label mapping and owner resolution, preserving stable direct addresses and reservations. A live title change that begins matching a rule removes the target even from an already-open session; removing a rule restores the same live target’s address on the next opening. Exclusions are visibility preferences, not a mechanism for preventing normal app activation or access to content.
